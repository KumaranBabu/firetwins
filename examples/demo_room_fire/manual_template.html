Room fire, from empty model to results

One complete job in PyFDS: build a room with a door and a window, set a growing gas fire and a heat detector, check the model, run the real FDS solver, and read the results. Every number and picture below comes from the case saved with this manual.

The case at a glance

A gas burner ignites in the middle of a single room. The fire grows for 15 seconds, then burns steadily. A heat detector under the ceiling above the fire and a column of four thermocouples record what the room does.

Building the model, step by step

The model is built through PyFDS's Python interface. Each step below shows what you ask for, what the program does with it, and the exact lines used. Every step is one undoable action, so a whole room can be taken back with a single undo.

1

Set up the calculation domain

YouGive the size of the box FDS will calculate in and how finely to divide it.

The cell size matters most near the fire. Cells of 0.15 m were chosen so the walls fall exactly on cell boundaries and the flame is resolved by about five cells across its width.

api.meshes.add_mesh(ijk=(40, 30, 20), xb=(0, 6.0, 0, 4.5, 0, 3.0), name="DOMAIN")
2

Add the room with a door and a window

YouChoose a wall material from the built-in library, then describe the room once.

The library supplies the double-layer gypsum wall and brings its gypsum board material with it. add_room then builds the four walls and the ceiling from the outline, and cuts the door and window as openings.

api.library.add_to_model("surfaces", "gypsum_wall_25mm")
api.geom.add_room([0.6, 5.4, 0.6, 3.9], height=2.4, wall_thickness=0.15,
                  ceiling_thickness=0.15, surf_id="GYPSUM_WALL_25MM",
                  openings=[{"side": "S", "centre": 3.0, "width": 0.9, "height": 2.1},
                            {"side": "E", "centre": 2.25, "width": 1.2, "height": 1.05, "sill": 0.9}])
3

Define the fire

YouCreate a burner surface with a heat release per square metre and a growth time, place it, and say what burns.

A negative growth time (tau_q=-15) means a t-squared ramp that reaches full output after 15 seconds. The burner is a small block on the floor in the middle of the room.

api.surfaces.add_typed("burner", name="BURNER_SURF", heat_release_rate=500.0, tau_q=-15.0)
api.obstructions.add_obstruction([2.7, 3.3, 2.1, 2.7, 0, 0.15], surf_id="BURNER_SURF", name="BURNER")
api.reactions.add_simple_reaction("PROPANE", 46000.0, soot_yield=0.01)
4

Open the outside

YouOne call closes the domain boundary with open vents.

Without it, air could not enter and smoke could not leave. Faces shared with another mesh would be skipped automatically (this case has only one mesh).

api.meshes.open_boundaries()
5

Place the instruments

YouTake the heat detector from the library and put sensors where you want readings.

det = api.library.add_to_model("heat_detectors", "heat_detector_74C", "HEAT_DET_PROP")
api.devices.add_device("LINK TEMPERATURE", [3.0, 2.4, 2.35], name="HEAT_DET", prop_id=det.name)
for z in (0.6, 1.2, 1.8, 2.3):
    api.devices.add_thermocouple([3.0, 2.4, z], f"TC_{round(z * 100):03d}")
api.devices.add_device("VELOCITY", [3.0, 0.75, 1.0], name="DOOR_VEL")
Check the library values for your own workThe heat detector entry (74 °C, RTI 5) is a typical value supplied as a starting point. Replace it with the data of the product you are modelling.
6

Ask for pictures and set the length of the run

YouAdd temperature slices through the fire, a visibility slice at head height, and the end time.

api.slices.add_slice("TEMPERATURE", plane="Y", position=2.4, name="SLICE_T_Y")
api.slices.add_slice("TEMPERATURE", plane="X", position=3.0, name="SLICE_T_X")
api.slices.add_slice("VISIBILITY",  plane="Z", position=1.5, name="SLICE_VIS_Z")
api.config.configure_simulation(t_end=20.0)

What the program checks for you

Before anything is run, PyFDS applies 28 model checks. Errors stop the run; warnings are shown and the run goes ahead. For this case the result was no errors and two warnings:

PassedMesh cell counts follow FDS's rule (2, 3 and 5 as factors), every opening lies inside a wall, no object sticks out of the domain, and every reference (surfaces, materials, detector property) resolves.
Warning 1 · Fire resolution is borderlineThe flame is resolved by about 4.9 cells (D*/dx); 10 or more is recommended for results you rely on. Halving the cell size would meet that but takes about eight times the computing time. Acceptable for a demonstration.
Warning 2 · Fuel species not definedPROPANE is used as the fuel name without its own species entry. FDS knows propane built in, so this run is unaffected.

The checks that guard the run are the same ones you can call at any time with api.validation.validate(). api.validation.gate() raises an error if a run would be blocked.

Running the simulation

PyFDS writes the FDS input file, starts the real FDS solver, watches its output, and indexes the result files. If FDS rejects the input, the run is reported as failed together with FDS's own error message.

result = api.execution.run("run", fds_binary="fds_smv/FDS6/bin/fds.exe")
# <OrchestratorResult success=True rc=0 wall=153.5s>

The input file that was run is saved as demo_room_fire.fds. It is plain FDS text, 40 lines, readable and usable in any other FDS tool.

Probing any point

The results can be queried at any point and time without opening a viewer. Values at the end of the run:

Point (x, y, z in m)Temperature at 20 s
Above the burner (3.0, 2.4, 1.2)482 °C
Under the ceiling above the burner (3.0, 2.4, 2.3)294 °C

A probe only answers where a slice was recorded. Points that are not on a saved slice plane return no value, so ask for a slice through the area you care about.

api.scene.open_results("run")
api.scene.add_slices()
api.scene.playback.seek_time(20.0)
api.scene.probe((3.0, 2.4, 1.2))

Opening and repeating the case

To run the whole demonstration again from nothing (about three minutes):

python examples/demo_room_fire/build_demo.py

To build, check and save it without running FDS:

python examples/demo_room_fire/build_demo.py --no-run

To open the saved project and its results for your own exploration:

from pyfds.api import FdsApi
from pyfds.io.serializer import Serializer

api = FdsApi(Serializer().load("examples/demo_room_fire/demo_room_fire.pyfds"))
api.scene.open_results("examples/demo_room_fire/run")

Changing the case is a matter of editing the numbers in the script, for example a larger fire (heat_release_rate), a wider door, or a longer run (t_end), then running it again.

Limits of this demonstration

  • It is a demonstration, not an engineering study. Twenty seconds of a small fire in coarse cells shows the workflow. The fire is only borderline resolved (see warning 1), and the room has not reached a steady state.
  • This walkthrough uses the Python interface. The desktop window of PyFDS is not part of it.
  • Library values are typical, not certified. Material and detector entries are starting points to be replaced with product data.
  • Movies need an encoder. PyFDS renders every frame of a slice with Smokeview. Joining the frames into a video file needs ffmpeg, which was not available when this case was made, so screenshots are provided instead.
  • Tested with: FDS 6.10.1 and Smokeview 6 on Windows. Other FDS versions may reject or accept different input keywords.
